## Missed points

- X-propagation (§X-Propagation (Xprop)): standard RTL simulation assigns
  predictable values when a control signal is unknown, so it can miss
  problems that gate-level simulation would detect; S10 enables Xprop in RTL
  simulation by default and makes it mandatory for coverage-closure
  regressions. This is the only place S10 links RTL simulation to gate-level
  simulation.
- Verification stages V1, V2, V3 (§Key Test Focus Areas, §Progressing
  towards V1/V3, §Defining Verification Complete): the effort is split into
  stages kept in lock-step with the design stages; V1 gives confidence the
  design is ready for integration, and V3 focuses on meeting regression and
  coverage goals and clearing warnings and TODOs. The pages mention "stages"
  but never name or describe them.
- Assertions (§Assertions): assertion monitors written for formal property
  verification are reused in simulation testbenches, and DV assertions are
  placed in interfaces bound to the design so they do not affect it.
- Integration testing of pre-verified sub-modules (§Integration Testing,
  §Chip Level DV): already-verified blocks are treated as black boxes, with
  only toggle coverage on their I/O collected, to prove they are connected
  properly; chip-level tests are simple C tests run on the processor core.
- Automation and reuse (§Automation, §Code Reuse): the initial testbench,
  the register model, and the documentation skeleton are auto-generated, and
  testbenches are built on shared base libraries; the heavy code sharing is
  the stated reason the sanity suite exists.
