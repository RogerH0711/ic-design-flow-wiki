What is an ASIC, and what is a design flow?

  • An ASIC is silicon manufactured to carry out one specific function.
  • The design flow: the steps from an idea to the data used for fabrication.
  • Each step is supported by electronic design automation (EDA) tools.
  • The work can last months; a proven flow keeps it on schedule.
  • From synthesis to the final layout file, it can run automatically.

The flow at a glance: five steps

  1. Design entry: describe the design in a hardware description language.
  2. Functional verification: confirm it behaves as required.
  3. Synthesis: convert the description into a netlist.
  4. Physical implementation: turn the netlist into a layout by floorplanning, placement, clock tree synthesis, and routing.
  5. Signoff: final checks before manufacturing.

Six words you need first

  • HDL (hardware description language): describes hardware; Verilog is one. RTL (register-transfer level): a high-level way of describing a circuit.
  • Netlist: standard cells and macros, and their connections.
  • Cell: another name for a CMOS logic gate.
  • A standard cell library typically has several sizes of one cell.
  • PDK (process design kit): files that describe one fabrication process to the tools.

Stage 1: Specification

One project's process (OpenTitan): the first of three broad stages.

  • A concept is written up as a brief proposal and goes through a request for comment.
  • After review, the full detailed specification is completed.
  • It is published to the wider team and refined from their comments.
  • Checked byup to three reviews, one a potential security review.

Stage 2: RTL design

  • The design is written in an HDL such as Verilog, normally at RTL.
  • Only a subset of Verilog can be synthesized.
  • Clocked logic uses non-blocking assignments; purely combinational logic uses blocking ones.
  • Flip-flops are used in place of latches unless a latch is absolutely necessary.
  • Risksimulation and synthesis disagreeing.

Stage 3: Functional verification

  • Goalthe design under test (DUT) behaves as its requirements say.
  • Simulation and formal verification are combined.
  • Both the RTL and, later, the gate-level netlist are verified.
  • Testing starts with a basic smoke test; stress tests exercise several features at once. All simulations run regularly as a regression.
  • In OpenTitan, done: every checklist item of every verification stage is ticked.

When have we tested enough? Coverage

  • Coverage answers the question of when testing is done.
  • Code coverage: extracted automatically by the simulator from lines, branches, and other structures.
  • Functional coverage: cover points that an engineer has to write.
  • Full code coverage shows all code ran, not that it does the right thing; both kinds are needed.
  • Gaps are closed with more tests or waived: coverage closure.

Stage 4: Logic synthesis

  • Inthe Verilog files and the timing constraints (an SDC file).
  • Software turns a higher-level description into a lower-level one that behaves the same.
  • Outa netlist, a circuit built from logic cells.
  • Two challenges: optimize the netlist, and map it onto gate types that physically exist.
  • Optimization can target area or timing; results are verified again by simulation.

Timing in one slide: setup, hold, slack

  • A flip-flop needs stable input before the clock edge (setup time) and after (hold time).
  • Setup violation: data arrives after it is required. Hold: before.
  • Slack: the margin between required and actual arrival time; it must be positive.
  • A violation shows up as negative slack; the flip-flop can go metastable.
  • Static timing analysis (STA) computes these times on every path.

Stage 7: Clock tree synthesis

  • Inthe placed design. Out: a well-balanced clock tree.
  • Clock buffers are inserted to balance the tree.
  • Clock skew: the clock arrives at different flip-flops at different times.
  • Skew is the main cause of hold violations, so it is reported and fixed.
  • Timing repair for setup and hold runs after this stage.

Stage 8: Routing

  • Two passes: a design must pass global routing without violations before detailed routing.
  • Global routing allocates the routing resources.
  • Detailed routing includes search and repair and its own DRC (design rule checking) engine.
  • Checked byzero violations, and an antenna check: a long wire can collect charge during fabrication and damage a transistor gate.
  • Problemcongestion stops global routing.

Stage 9: Layout finishing

  • The automated flow calls its last stage layout generation.
  • Metal fill adds floating metal shapes so that density rules are met.
  • Parasitics extraction computes the resistance and capacitance of the routed wires.
  • Outthe final layout in GDSII form.
  • Final timing is reported as worst slack, total negative slack, and worst negative slack.

Stage 10: Signoff

Physical and timing verification before manufacturing.

  • DRC (design rule checking): the layout against the foundry's manufacturing rules.
  • LVS (layout versus schematic): both have the same connectivity.
  • STA: on the fully implemented design.
  • Antenna check: looks for antenna violations.
  • Then tape-out: the design goes to a fabrication facility.
